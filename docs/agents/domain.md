# Domain docs

This repo uses a single context. Before exploring, read the root
`GLOSSARY.md` and any relevant architecture decision records in
`docs/adr/`. Skip either source if it does not exist.

Use glossary terms in issue titles, designs, and tests. Bring unresolved
terms to `/domain-modeling` and record them in `GLOSSARY.md` once agreed.

If a proposal conflicts with an existing ADR, name the decision and
explain why it should be revisited. Record new decisions in `docs/adr/`
as they are made.
